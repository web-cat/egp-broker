# Plan 2.2: PassPort Admin Registration & Public Callback Endpoints

<objective>
Implement the HTTP endpoints for triggering dynamic registration from the admin console and receiving credentials callbacks from external learning tools, with dedicated unit test suites.

Purpose: Exposes the API surface for the 2-Phase Dynamic Registration Handshake conforming to Nuxt 4 server conventions.
Output: Two Nitro API endpoints and two passing Vitest test suites.
</objective>

<tasks>

<task type="auto">
  <name>Create Admin Registration Trigger and Public Callback Endpoints</name>
  <files>server/api/admin/tools/[id]/passport/register.post.ts, server/api/passport/v1/credentials.post.ts</files>
  <action>
    1. Create `server/api/admin/tools/[id]/passport/register.post.ts`:
       - Validate admin session via `getUserSession(event)`. If not ADMIN, throw 403.
       - Extract tool ID from `getRouterParam(event, 'id')`.
       - Call `initiatePassPortRegistration(id, event)`.
       - Return `{ statusCode: 200, data: toolRow }`.
    2. Create `server/api/passport/v1/credentials.post.ts`:
       - Extract `token` query parameter via `getQuery(event).token as string`.
       - Read body via `readBody(event)`.
       - Call `handlePassPortCredentialsDelivery(token, body)`.
       - Return `{ statusCode: 200, data: { success: true, message: 'PassPort credentials registered successfully' } }`.
    AVOID: Requiring authentication on the credentials callback endpoint (it is an asynchronous webhook called by external tools).
  </action>
  <verify>test -f server/api/admin/tools/[id]/passport/register.post.ts && test -f server/api/passport/v1/credentials.post.ts</verify>
  <done>Both endpoints created following Nuxt 4 server conventions.</done>
</task>
