# Plan 2.2: Student Reservation Server API Endpoints & Verification

## Objective

Expose the student-facing CBTF endpoints under `/api/me/cbtf/`: availability recommendations, reservation booking, rescheduling, and cancellation. Enforce single-booking constraints, 5-minute slot alignments, arrival limits, and transactional seat assignments per the Nuxt 4 and `GEMINI.md` standards.

<task type="auto">
  <name>Create Reservation Booking, Reschedule, and Cancellation Endpoints</name>
  <files>server/api/me/cbtf/reservations.get.ts, server/api/me/cbtf/reservations.post.ts, server/api/me/cbtf/reservations/[id].patch.ts, server/api/me/cbtf/reservations/[id].delete.ts</files>
  <action>
    Implement student reservation endpoints:
    1. `GET /api/me/cbtf/reservations`: Returns active and past reservations for the authenticated user, projected with `cbtfReservationRowSchema`.
    2. `POST /api/me/cbtf/reservations`:
       - Validates body with `createReservationInputSchema`.
       - Prevents double-booking: checks if user already has a `SCHEDULED` or `CHECKED_IN` reservation for this assignment.
       - Validates 5-minute alignment (`minutes % 5 === 0`, `seconds === 0`).
       - Validates slot falls within the student's scheduling window (or retake pass window).
       - In a Prisma `$transaction`: validates arrival throttle, finds next available seat in sequence, and creates `CbtfReservation`.
    3. `PATCH /api/me/cbtf/reservations/[id]`:
       - Validates body with `rescheduleReservationInputSchema`.
       - Verifies reservation belongs to student and is in `SCHEDULED` or `MISSED` status.
       - Validates new slot within student's scheduling window.
       - In a Prisma `$transaction`: re-verifies capacity & throttle, re-assigns seat, and updates reservation.
    4. `DELETE /api/me/cbtf/reservations/[id]`:
       - Allows student to cancel a `SCHEDULED` reservation before it starts (sets status `CANCELLED`).
  </action>
  <verify>docker compose exec app-dev pnpm vitest run test/unit/server/api/me/cbtf-reservations.test.ts</verify>
  <done>All reservation lifecycle endpoints are implemented, validated with Zod, and protected by transactions.</done>
</task>
