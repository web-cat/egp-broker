# Plan 1.1: Prisma Schema Extension & Database Migration

<objective>
Extend the Prisma schema to support the dual-role architecture for LtiTool (LTI Proxy vs PassPort Extension) with separate credentials, dynamic registration status tracking, and token binding, then generate and apply the database migration.

Purpose: Establishes the persistent data foundation required for PassPort dynamic registration and extension webhook delivery.
Output: Updated `prisma/schema.prisma` and applied Prisma migration SQL.
</objective>

<context>
Load for context:
- .gsd/SPEC.md
- .gsd/DECISIONS.md
- prisma/schema.prisma
- docs/extension-api.md
</context>

<tasks>

<task type="auto">
  <name>Add PassPortRegistrationStatus enum and extend LtiTool model in Prisma schema</name>
  <files>prisma/schema.prisma</files>
  <action>
    Update `prisma/schema.prisma`:
    1. Define enum `PassPortRegistrationStatus`:
       - `NOT_REGISTERED`
       - `PENDING`
       - `REGISTERED`
       - `FAILED`
    2. Add fields to model `LtiTool`:
       - `supportsProxy Boolean @default(true)`
       - `supportsPassport Boolean @default(false)`
       - `supportsExtensionApi Boolean @default(false)` (retained for backward compatibility)
       - `passportClientId String?`
       - `passportClientSecret String?`
       - `passportRegistrationUrl String?`
       - `passportExtensionUrl String?`
       - `passportRegistrationToken String? @unique`
       - `passportRegistrationStatus PassPortRegistrationStatus @default(NOT_REGISTERED)`
       - `passportRegistrationError String?`
       - `passportRegisteredAt DateTime?`
       - `passportRequestedProperties Json?`
    AVOID: Dropping existing columns or modifying `id`, `platformId`, `assignments`, or existing relations.
  </action>
  <verify>grep -q "PassPortRegistrationStatus" prisma/schema.prisma && grep -q "passportRegistrationToken" prisma/schema.prisma</verify>
  <done>Prisma schema contains PassPortRegistrationStatus and all specified LtiTool fields.</done>
</task>

<task type="auto">
  <name>Generate and apply Prisma migration inside app-dev Docker container</name>
  <files>prisma/schema.prisma</files>
  <action>
    Execute migration inside container:
    `docker compose exec app-dev pnpm prisma migrate dev --name add_passport_lti_tool_fields`
    Regenerate the Prisma client inside container:
    `docker compose exec app-dev pnpm prisma generate`
    AVOID: Running `prisma db push` (violates Constitution section III). Always use `prisma migrate dev`.
  </action>
  <verify>docker compose exec app-dev pnpm prisma migrate status</verify>
  <done>Migration created, applied, and database schema is up-to-date with 0 pending migrations.</done>
</task>

</tasks>
