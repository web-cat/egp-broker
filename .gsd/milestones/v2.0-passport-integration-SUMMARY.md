# Milestone: v2.0 — PassPort Integration

## Completed: 2026-09-06

## Deliverables

- ✅ **Dual-Role LtiTool Schema**: Extended `LtiTool` with `supportsProxy` and `supportsPassport`, independent credential pairs (`key`/`secret` for Proxy, `passportClientId`/`passportClientSecret` for PassPort), registration token, status enum (`NOT_REGISTERED`, `PENDING`, `REGISTERED`, `FAILED`), error tracking, and requested properties metadata.
- ✅ **Shared Schemas & Type Contracts**: Zod validation schemas and TypeScript types for PassPort v1 registration payloads, extension requests, rollback requests, and tool projections in `shared/models/passport.ts` and `shared/models/tool.ts`.
- ✅ **2-Phase Dynamic Registration Handshake**:
  - Phase 1 dispatch endpoint (`POST /api/admin/tools/:id/passport/register`) generating secure cuid tokens and sending registration payloads to external tool endpoints.
  - Phase 2 callback endpoint (`POST /api/passport/v1/credentials?token=<cuid>`) validating tokens, persisting credentials and extension URLs, and updating tool status to `REGISTERED`.
- ✅ **Admin Tool Management UI**: Extended `ToolEditPanel.vue` and `/admin/tools` with independent role toggles, dedicated credential inputs, registration trigger action station with status badges, error banners, and toast alerts.
- ✅ **Cryptographic Request Signer**: Built `signPassPortRequest` generating HMAC-SHA256 hex signatures and Unix timestamps with `X-PassPort-Client-ID`, `X-PassPort-Signature`, and `X-PassPort-Timestamp` HTTP headers.
- ✅ **Privacy Property Filtering**: Implemented `buildPassPortExtensionPayload` including baseline properties and strictly filtering optional context, user, and resource fields based on `passportRequestedProperties`.
- ✅ **Fail-Fast Pass Redemption Hook**: Integrated extension dispatch into `server/utils/redemptions.ts` within transactional boundaries. If tool sync fails, redemption immediately aborts, student pass balance is preserved, an urgent `ntfy` alert is triggered, and a friendly guidance message is returned.
- ✅ **Downstream Rollback Recovery**: Automated signed `DELETE` request dispatch (`sendPassPortRollback`) if downstream database commits or LMS sync fail after tool acknowledgment.

## Lessons Learned & Key Decisions

- **Tokenized Query Callbacks ([DECISION-006](file:///Users/edwards/git/egp-broker/.gsd/DECISIONS.md#L114)):** Binding Phase 2 credential receipt directly to the unique registration token in the callback URL query string (`?token=<cuid>`) prevents spoofing, eliminates race conditions, and guarantees deterministic tool matching.
- **Fail-Fast Transaction Safety ([DECISION-007](file:///Users/edwards/git/egp-broker/.gsd/DECISIONS.md#L133)):** Performing external extension dispatch within the redemption transaction ensures that network or tool-side errors immediately roll back pass deductions, preventing students from ever losing passes due to third-party outages.
- **Dual-Role Segregation ([DECISION-008](file:///Users/edwards/git/egp-broker/.gsd/DECISIONS.md#L157)):** Keeping `supportsProxy` and `supportsPassport` independent with isolated credentials allows tools to act purely as LTI launch proxies, purely as PassPort extension handlers, or as unified hybrid tools.
