<task type="auto">
  <name>Implement request signer, payload builder, extension dispatcher, and rollback dispatcher in server/utils/passport.ts</name>
  <files>server/utils/passport.ts</files>
  <action>
    1. Implement `signPassPortRequest(secret: string, body: unknown, timestamp?: number)`:
       - Uses `node:crypto` `createHmac('sha256', secret)`.
       - Serializes body to JSON string if not already string.
       - Generates hex digest. Returns `{ signature, timestamp: timestamp ?? Math.floor(Date.now() / 1000) }`.
    2. Implement `buildPassPortExtensionPayload(params)`:
       - Parameters:
         - `context`: `{ lmsInstanceGuid, issuer, ltiContextId, lmsInstance?, ltiDeploymentId?, canvasCourseId? }`
         - `user`: `{ ltiUserId, brokerUserId?, canvasUserId?, firstName?, lastName?, email?, displayName?, courseRole? }`
         - `resource`: `{ ltiResourceLinkId, brokerAssignmentId?, canvasAssignmentId?, title?, externalUrl? }`
         - `extension`: `{ passType, originalDueDate, newDueDate, appliedAt }`
         - `requestedProperties`: `string[] | null | undefined`
       - Generates unique UUID v4 `request_id`.
       - Baseline fields always included:
         - Context: `lms_instance_guid`, `issuer`, `lti_context_id`.
         - User: `lti_user_id`.
         - Resource: `lti_resource_link_id`.
         - Extension: all fields mandatory (`pass_type`, `original_due_date`, `new_due_date`, `applied_at`).
       - Optional fields: included ONLY if explicitly present in `requestedProperties` (e.g. `canvas_course_id`, `email`, `canvas_assignment_id`, etc.).
       - Validates against `passPortExtensionPayloadSchema.parse(...)`.
    3. Implement `sendPassPortExtension(tool: Pick<LtiTool, 'passportClientId' | 'passportClientSecret' | 'passportExtensionUrl'>, payload: PassPortExtensionPayload)`:
       - Validates presence of `passportExtensionUrl`, `passportClientId`, and `passportClientSecret`.
       - Serializes payload and signs with `signPassPortRequest`.
       - Dispatches POST via `$fetch` with headers:
         - `Content-Type: application/json`
         - `X-PassPort-Client-ID`: `tool.passportClientId`
         - `X-PassPort-Signature`: `signature`
         - `X-PassPort-Timestamp`: String(timestamp)
       - Uses 10-second timeout signal (`AbortSignal.timeout(10000)`).
       - Throws error if non-2xx response or network failure.
    4. Implement `sendPassPortRollback(tool: Pick<LtiTool, 'passportClientId' | 'passportClientSecret' | 'passportExtensionUrl'>, requestId: string)`:
       - Validates credentials and endpoint.
       - Creates payload `{ request_id: requestId }` conforming to `passPortRollbackPayloadSchema`.
       - Signs with `signPassPortRequest`.
       - Dispatches DELETE via `$fetch` with same headers and timeout.
  </action>
  <verify>docker compose exec -T app-dev pnpm test:unit test/unit/shared/models/passport.test.ts</verify>
  <done>Core PassPort request signing, property filtering, and HTTP transport utilities implemented.</done>
</task>
