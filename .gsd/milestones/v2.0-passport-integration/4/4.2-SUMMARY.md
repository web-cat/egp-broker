# Plan 4.2: Pass Redemption PassPort Hook, Fail-Fast Alerting & Rollback Safety — Summary

## Changes Made

1. **`server/utils/redemptions.ts`**:
   - Updated `redeemPass` to query the associated `tool: { include: { platform: true } }` and course deployment platform.
   - Enhanced user query to include `ltiIdentities` and retrieve course enrollment role.
   - Added PassPort pre-check: if `assignment.tool?.supportsPassport` is true, verifies that the tool's status is `REGISTERED` and credentials (`passportExtensionUrl`, `passportClientSecret`) are present. If unready, triggers `notifyPassPortSyncFailure` and aborts with HTTP 502 ("External tool is not registered for PassPort extensions. Please contact your instructor.").
   - Privacy-filtered payload construction via `buildPassPortExtensionPayload`, adhering strictly to the tool's `passportRequestedProperties`.
   - Dispatches `sendPassPortExtension(tool, payload)`. If the tool fails to accept the extension (non-2xx or timeout), catches error, calls `notifyPassPortSyncFailure`, and throws HTTP 502 ("External tool extension sync failed. Please contact your instructor for assistance.").
   - Transaction fail-fast guarantee: Because the error is thrown inside `prisma.$transaction`, all database modifications (pass deduction, redemption creation) automatically roll back, preserving the student's pass balance.
   - Downstream failure recovery: If an unexpected error occurs downstream (after `sendPassPortExtension` succeeds but before function returns), catches error and asynchronously calls `sendPassPortRollback(tool, payload.request_id)` to ensure state consistency with the external tool.

2. **`test/unit/server/utils/redemptions-passport.test.ts`**:
   - Implemented 5 unit tests verifying:
     - Normal redemption without tool or when `supportsPassport === false`.
     - Successful PassPort extension dispatch when tool is registered.
     - Fail-fast rejection when tool is not registered or credentials missing.
     - Fail-fast abortion, error alert dispatch, and balance preservation when tool extension fails.
     - Signed rollback `DELETE` dispatch if a downstream database error occurs after tool extension dispatch.
