# Plan 2.1: Server Registration Orchestrator & Utilities — Summary

## Completed: 2026-09-06

### What was done

1. **Implemented PassPort Registration Orchestration (`server/utils/passport.ts`)**:
   - `initiatePassPortRegistration(toolId, event)`:
     - Retrieves tool by ID, validates existence and presence of `passportRegistrationUrl`.
     - Generates cryptographically secure `registrationToken` using `randomUUID()`.
     - Updates database record: sets status to `PENDING` and records `passportRegistrationToken`.
     - Builds compliant PassPort Phase 1 payload (`broker_base_url`, `callback_url` with token param, `name: 'EGP Broker'`, `passport_version: '1.0'`).
     - Dispatches outbound HTTP POST to tool registration URL via `$fetch`.
     - Handles failure: catches HTTP/network errors, marks tool status `FAILED`, records `passportRegistrationError`, and throws a 502 Bad Gateway error.
   - `handlePassPortCredentialsDelivery(token, body)`:
     - Validates presence of token query parameter.
     - Validates request payload against `passPortPhase2CredentialsSchema`.
     - Matches pending tool with matching `passportRegistrationToken` and `PENDING` status.
     - Persists client credentials (`passportClientId`, `passportClientSecret`), `passportExtensionUrl`, and `passportRequestedProperties`.
     - Sets status to `REGISTERED`, records timestamp `passportRegisteredAt`, clears error, and nullifies single-use token.
2. **Exported Projection Utility (`server/utils/lti-tools.ts`)**:
   - Exported `toToolRow` to ensure consistent projection mapping across tool CRUD and PassPort registration.
3. **Comprehensive Unit Testing (`test/unit/server/utils/passport.test.ts`)**:
   - 9 test cases covering 404/400 validations, successful Phase 1 dispatch, error trapping/failure transitions, token mismatch, invalid body payloads, and successful Phase 2 credential persistence.
