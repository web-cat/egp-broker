# Plan 1.1: CBTF Prisma Schema Models & Database Migration

## Objective

Establish the database foundations for the Computer-Based Testing Facility (CBTF). Update the Prisma schema to introduce the `PROCTOR` global role, student ID identification on users, assignment scheduling windows, and five new core CBTF models (`CbtfFacility`, `CbtfOperatingHours`, `CbtfScheduleException`, `CbtfProctorShift`, `CbtfReservation`), followed by applying a clean migration within the development container.

## Context

- `.gsd/SPEC.md`
- `.gsd/REQUIREMENTS.md`
- `prisma/schema.prisma`
- `GEMINI.md` (Docker-based migrations via `docker compose exec app-dev pnpm prisma migrate dev`)

## Tasks

<task type="auto">
  <name>Update Prisma Schema</name>
  <files>prisma/schema.prisma</files>
  <action>
    Modify `prisma/schema.prisma`:
    1. Add `PROCTOR` to enum `GlobalRole`.
    2. Add `studentId String? @unique` to model `User` with relations to `CbtfReservation[]` and `CbtfProctorShift[]`.
    3. Add scheduling fields to `Assignment`:
       - `isSchedulable Boolean @default(false)`
       - `scheduleWindowStart DateTime?`
       - `scheduleWindowEnd DateTime?`
       - `cbtfReservations CbtfReservation[]`
    4. Add enum `CbtfReservationStatus`:
       - `SCHEDULED`
       - `CHECKED_IN`
       - `COMPLETED`
       - `MISSED`
       - `CANCELLED`
    5. Add models:
       - `CbtfFacility` (id, name, totalSeats, seatAllocationOrder, createdAt, updatedAt, and relations).
       - `CbtfOperatingHours` (id, facilityId, dayOfWeek, openTime, closeTime, createdAt, updatedAt).
       - `CbtfScheduleException` (id, facilityId, date, isClosed, openTime, closeTime, reason, createdAt, updatedAt).
       - `CbtfProctorShift` (id, facilityId, userId, date, startTime, endTime, createdAt, updatedAt).
       - `CbtfReservation` (id, facilityId, assignmentId, userId, seatNumber, startTime, endTime, status, checkedInAt, checkedOutAt, checkedInByUserId, checkedOutByUserId, createdAt, updatedAt).
    Ensure all models have proper indexes (`@@index`, `@@unique`) and follow Prisma conventions outlined in `GEMINI.md`.
  </action>
  <verify>docker compose exec app-dev pnpm prisma validate</verify>
  <done>Prisma schema validates successfully with no syntax or relational errors.</done>
</task>

<task type="auto">
  <name>Run Prisma Migration and Client Generation</name>
  <files>prisma/schema.prisma, prisma/migrations/*</files>
  <action>
    Generate and execute the migration inside the Docker environment:
    `docker compose exec app-dev pnpm prisma migrate dev --name add_cbtf_scheduler_models`
    Verify that the migration completes, creates a new migration directory in `prisma/migrations/`, and updates the generated `@prisma/client`.
  </action>
  <verify>docker compose exec app-dev pnpm prisma status</verify>
  <done>Database schema is up to date with new CBTF tables, indexes, and enums.</done>
</task>

## Success Criteria

- [ ] `prisma/schema.prisma` contains all required CBTF models, enums, and relation fields.
- [ ] Database migration `add_cbtf_scheduler_models` is applied cleanly in PostgreSQL.
- [ ] Prisma Client is generated and exports all new models and types.
