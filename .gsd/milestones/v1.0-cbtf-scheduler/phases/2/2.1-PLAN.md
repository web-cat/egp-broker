# Plan 2.1: Core Scheduling & Seat Allocation Engine

## Objective

Implement the server-side business logic and algorithms in `server/utils/cbtf.ts` for the Computer-Based Testing Facility. This includes date-specific operating hours and exception resolution, 5-minute boundary slot generation, arrival throttling enforcement ($\le \lceil \text{total\_seats} / 12 \rceil$), sequential seat allocation engine, progressive narrowing query algorithm, student scheduling window calculation (with retake pass support), and rigorous unit tests.

## Tasks

<task type="auto">
  <name>Implement CBTF Scheduling & Allocation Utilities</name>
  <files>server/utils/cbtf.ts</files>
  <action>
    Create `server/utils/cbtf.ts` with the following core functions:
    1. `getFacilityOperatingHoursForDate(facilityId: string, targetDate: Date, tx?: PrismaClient)`:
       - Checks `CbtfScheduleException` for `targetDate`. If found and `isClosed: true`, returns closed. If custom hours, returns them.
       - Otherwise queries `CbtfOperatingHours` for `targetDate.getDay()`. If found, returns open/close times; otherwise returns closed.
    2. `generateAvailableSlotsForDate(facility, targetDate, existingReservations)`:
       - Generates 5-minute boundary slots between openTime and (closeTime - 60 minutes).
       - Enforces arrival throttle: count of reservations starting at `slotTime` must be strictly less than `Math.ceil(facility.totalSeats / 12)`.
       - Enforces total seat occupancy: count of overlapping 1-hour reservations spanning `[slotTime, slotTime + 60m)` must be less than `facility.totalSeats`.
    3. `assignNextSeat(seatAllocationOrder: number[], slotStart: Date, slotEnd: Date, activeReservations: { seatNumber: number }[], lastAssignedSeat?: number)`:
       - Follows the definable sequence order of seats.
       - Identifies occupied seats during the 1-hour window.
       - Selects the next available seat in the allocation sequence after `lastAssignedSeat`, wrapping around if needed.
    4. `getStudentSchedulingWindow(userId: string, assignment: Assignment, tx?: PrismaClient)`:
       - Checks for existing `PassRedemption` on this assignment for this student.
       - If redemption exists, effective window is `[redemption.availableFrom ?? redemption.createdAt, redemption.acceptUntil ?? redemption.dueDate]`.
       - Otherwise, effective window is `[assignment.scheduleWindowStart, assignment.scheduleWindowEnd]`.
    5. `getRecommendedDaysAndSlots(facility, assignment, studentWindow, preference: 'morning' | 'afternoon', selectedDate?: string)`:
       - Step 1: Filters slots by preference (morning: < 12:00, afternoon: >= 12:00).
       - Step 2: Aggregates open slots and utilization across days within student window; recommends 3-4 days with highest open slot availability.
       - Step 3: For selected day, groups open slots by hour and randomly picks 1 available slot per hour.
  </action>
